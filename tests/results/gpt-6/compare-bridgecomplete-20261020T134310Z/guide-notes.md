# Bridge native SFT evidence

Both the seeded tiny Qwen3 and the actual local pretrained Qwen3-0.6B completed native Bridge conversion, provider construction, checkpoint restore, forward/backward, one real optimizer step, final checkpoint save and return from `megatron.bridge.training.finetune.finetune`. Each has a separate clean CPU Transformers forward/backward/SGD reference initialized from exactly equal stored values. [INDEX.json](INDEX.json) pins the executed sources and archive hashes; [VALIDATION.json](VALIDATION.json) records validation scope.

The executed route is the Slime-prescribed `fzyzcjy/Megatron-Bridge` fork `0.3.0rc0` at `35b4ebfc486fb15dcc0273ceea804c3606be948a`, MCore `3714d81d418c9f1bca4594fc35f9e8289f652862`, and official MindSpeed `fc63de5c48426dd019c3b3f39e65f5bdf56e4086`, with the source patches and API adaptations recorded in the archives. This is a source-adapted native execution result. Untouched NVIDIA Bridge `v0.6.2` at `c0e164ed2aedac4ad1c877780e2564a19d5d54ec`, its exact MCore gitlink `a0f793dfa4e776d99a8aa63bed74e0fafc91b0db` and TransformerEngine `15288857644368b8b7bdddd9bead7d6d3d04de80` remain a separate failed CUDA/NVCC dependency baseline.

The native entrypoints were `AutoBridge.from_hf_pretrained` → `AutoBridge.to_megatron_provider` → `GPTModelProvider.provide_distributed_model` → `AutoBridge.save_megatron_model` → fresh-process native `finetune`. Conversion produced a native `torch_dist` checkpoint which the native trainer restored. Full SFT was used; no LoRA.

Execution used real Ascend910_9382 devices, torch `2.8.0+cpu` with real `torch_npu 2.8.0`, CANN9.1.0 and driver25.5.2. MindSpeed loads the official `torch_npu.contrib.transfer_to_npu` compatibility adapter. There were no user-created CUDA/operator stubs. The native numerical operations ran on NPU. The published Slime recipe uses CANN8.5.0, so this result does not assert official support for the complete dependency combination.

The disclosed adaptations are:

- Preload genuine ModelOpt before MindSpeed to avoid circular plugin discovery; use a dependency overlay for missing native trainer imports.
- Populate missing provider fields from MindSpeed's own defaults, set microbatch1/use_flash_attn, and retain the actual HF `head_dim` explicitly.
- Run conversion and finetune in separate fresh native processes to respect Megatron's rerun singleton lifecycle.
- Map the old Bridge optimizer positional defaults to MCore's `config_overrides=None`, asserting absent custom decay/LR predicates and `lr_mult=1`; supply disabled decoupled-LR fields used by obsolete logging references.
- Provide a fixed DatasetProvider and observation wrappers around native setup and optimizer calls. The actual optimizer executes first. Already-captured gradients are subsequently mapped through Bridge using temporary parameter storage, then original storage is restored before native saving.
- Use a short symlink to persistent temporary storage for native AF_UNIX checkpoint-manager sockets. Full original logs retain DTFS busy-file cleanup warnings after native workflow return.

Native parameters and output logits were BF16; native main gradients and optimizer masters were FP32. The independent CPU parameters, gradients and logits were FP32. Stored BF16 NPU updates and stored FP32 CPU updates therefore include quantization differences. Both used seed20261020, dropout0, TP1/PP1/CP1/DP1, batch1, one microbatch, stateless SGD at learning rate0.001, no momentum, weight decay or clipping. Stateful optimizer restoration does not apply to this optimizer.
