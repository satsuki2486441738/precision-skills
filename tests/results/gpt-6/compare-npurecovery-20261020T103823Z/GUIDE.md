# Native evaluation and recovery guide

## What this run measures

The frozen branch covers 16 unique libraries and 17 task lanes because ms-swift has separate SFT and RL lanes. Fourteen source-scoped lanes completed native model execution; three untouched upstream lanes reached specific dependency/backend boundaries without completing their native workflows. There are 28 canonical cases: 27 have independent references and Slime does not. The recorded canonical comparisons comprise 107 core CLI operations. None has a numerical acceptance threshold. The parent reused the existing branch and original 16-device instance, coordinated the previously cold-started workers, reviewed their actual captures and replayed exported artifacts independently. This continuation does not measure independent agent-model quality.

[results.json](results.json) owns the final per-lane status, evidence cutoff and archive inventory. Distinguish a complete native pipeline from a partial native failure, a dependency/build attempt and an independent precision comparison. Imports, help commands, editable installs, successful compilation and small NPU tensor operations are preparation evidence only. `thresholds: null` and `no_thresholds` mean metrics were computed; they do not mean numerical acceptance.

The canonical SFT matrix has four frameworks (TRL SFTTrainer, LLaMAFactory, ms-swift and Axolotl), each with tiny/pretrained and BF16-requested/FP32 cases. These are one-step plumbing and precision observations. The tiny models are explicitly seeded fixtures. The pretrained cases use Qwen3-0.6B with LoRA. Different native chat/completion templates have different target sets and reductions, so their losses are compared to each framework's own matched reference, not ranked across frameworks. [matrix.json](sft/matrix.json) records actual parameter storage through `native_parameter_dtypes`, target counts, native losses, frozen-state checks and metrics. Logit and gradient dtypes belong to each case's capture/metric environment, not that matrix field. Three earlier completed retries are historical metadata, not additional matrix coverage.

## Why the original instance appeared unusable

The notebook web interface worked, but there was no SSH listener. Its vendor Apache MINA service startup invoked bare `java`, which was absent from PATH despite an installed absolute JRE. Starting the JRE exposed a second error: the optional EdDSA security provider was missing. The unchanged vendor service jar was relaunched with the absolute JRE and the official `net.i2p.crypto:eddsa:0.3.0` provider on its classpath. The provider SHA256 was `4dda1120db856640dbec04140ed23242215a075fe127bdefa0dcfa29fb31267d`. The previous authorized key was restored while preserving the platform key and a backup. Listener, server-key identity and authenticated interactive access were verified.

This is a service-process repair, not a platform-wide startup fix. A later Pod replacement can reset home-directory files again. The server supports an interactive shell but closes SSH exec channels; task scripts therefore used a pinned-host-key interactive stdio transport with per-chunk and final SHA256 checks. No private key was uploaded or included in public evidence.

The current Pod differs from the earlier failed-job Pod. The old material directory is absent, and mount inspection identifies that toolkit directory as Kubernetes `emptyDir`, despite its separate ext4 appearance. The earlier claim that a separate mount established persistence was incorrect. [Kubernetes documents the Pod-lifetime boundary](https://kubernetes.io/docs/concepts/storage/volumes/#emptydir). Current environments, sources, checkpoints and artifacts are on the actual DTFS shared mount. The old uncollected job outcomes remain unknown. No new instance was created.

## Environment and launch conditions

Authenticated inspection found aarch64 Linux, 16 logical Ascend910_9382 devices with 64 GiB HBM each, driver25.5.2 and CANN9.1.0. The original Python3.12 runtime had Torch2.9.0+cpu and TorchNPU2.9.0.post2. Private task environments selected explicit compatible revisions where available. The pinned [Ascend compatibility table](https://github.com/Ascend/pytorch/blob/cf04f800cdebb3bdb650085d746b5433e869f145/COMPATIBILITY.en.md) pairs CANN9.1 with, among others, Torch2.7.1/NPU2.7.1.post8, Torch2.9/NPU2.9.post6 and Torch2.10/NPU2.10.post4. A successful operation under another combination is not proof that its entire deployment set is officially supported.

Source the installed vendor CANN `set_env.sh` before initializing NPU Python. Preserve its PYTHONPATH entries: dropping them broke the actual pyACL import. Use isolated environments and explicit interpreters. The inherited platform `LOCAL_RANK` was a comma-separated device list, not an integer. Task entrypoints removed stale inherited distributed controls before native Ray/torchrun assigned real worker ranks. Valid native worker ranks must be retained.

Long DTFS temporary paths exceeded AF_UNIX/ZMQ socket limits. Keep only transient IPC paths short; persist environments, model data, compiler outputs, logs and evidence. CANN can additionally validate a real temporary path against TMPDIR, so a symlink-only shortening strategy must be tested rather than assumed valid. Framework/Triton compile pools need their own concurrency controls; `MAX_JOBS` alone does not bound Torch Inductor workers. All repairs were limited to task-owned environments/processes; no global driver or kernel-security change was made.

## Native execution and independent references

SFT collectors call the real `SFTTrainer.train`, LLaMAFactory `run_exp`, Swift `sft_main` or Axolotl trainer pipeline. Copy-only observations retain the prepared batch, effective loss denominator, initial parameters, gradients at optimizer entry and actual stored post-step parameters. Frozen parameter values are hashed before and after. A fresh CPU FP32 process reloads the source model and equal initial trainable state, then independently computes forward, loss, backward and SGD. It never substitutes native gradients or updates into the reference.

Requested precision is not treated as measured dtype. One LLaMAFactory "FP32" attempt still had BF16 frozen weights; it was retained as historical mixed precision and replaced in canonical coverage by an explicit genuine-FP32 loading case. Swift patches NPU normalization globally during import, so its CPU reference uses a clean interpreter. Axolotl's all-masked tiny chat fixture was rejected; canonical completion cases use an explicit full-sequence target policy. A scoped capability guard handles a CPU-Torch CUDA-query AssertionError by truthfully reporting no CUDA FP8 support; it does not fake device availability.

MindSpeed-LLM calls the official `pretrain_gpt.main` workflow and native optimizer. Its compact canonical fixture has 770,432 parameters, nine gradient tensors and 16 legal targets. The CPU reference maps the official Megatron QKV/FC1 layouts to an equivalent eager model and checks initial values exactly. An earlier mock-data attempt used targets outside the actual padded vocabulary. It executed, but was rejected as an invalid token contract; it is not counted as a valid precision case. A larger valid native fixture is retained privately as historical evidence rather than duplicated in the public bundle.

llama.cpp uses the official CANN backend at commit `d8d92973c8c21bb4dd5d592f0fec26fe2cd1e654`, compiled for Ascend910_9382. Qwen3-0.6B and Qwen3-0.6B-Base are converted by the official converter to unquantized F16 GGUFs. Separate CPU and CANN executions load the identical GGUF, use F16 KV storage and perform native prefill plus two cached decode calls with explicit fixed token histories. Logs verify complete 29/29 layer offload. Raw F32 logits and all 151,936 vocabulary coordinates are retained. Six shipped comparison CLI calls cover tensors, distributions and target scores across the two models.

LMDeploy completed the real PyTorch Ascend Qwen3 pipeline for Qwen3-0.6B and Qwen3-0.6B-Base. The [LMDeploy bundle](lmdeploy-native-evidence.zip) retains the successful native/clean-CPU executions and earlier dependency/interface failures. Four rows per case map from actual input IDs and positions to one prefill plus three decode predictions; warmup calls are excluded by `validate_history`. Native F16 logits are copied at the original `Qwen3ForCausalLM.get_logits` return before processors. The generation Response API did not expose logits. Six actual core CLI calls and fresh-package replays cover raw tensors, derived distributions and target scores. The reference loads checkpoint weights as F16 then promotes to F32 and evolves its own F32 KV cache; native paged KV is observed F16. Those differences are explicit per-side conditions. Checkpoint/config/tokenizer file hashes are recorded, but individual native loaded parameter values were not compared to CPU. The kernel repair changes only an initializer import path and aliases to existing functions, with no numerical-function AST change. Kernel dependency metadata still conflicts with the installed Torch/TorchNPU/Triton revisions; this environment is not called clean.

MindIE-LLM calls the official PARunner/ModelRunner/ATB PagedAttention path. It generated four real tokens from Qwen3-0.6B and retained four native BF16 full-vocabulary logit rows, excluding warmup. The clean CPU reference replays the exact native history. Checkpoint hashes are unchanged before/after and match the source model. The official file-ownership check was satisfied with a byte-identical task-owned copy, not bypassed. Missing host `lspci` was supplied by privately unpacking official ARM pciutils/runtime packages and reading real hardware. Three core comparisons cover logits/NLL observations, distributions and target scores; see the [MindIE index](mindie/archive-index.json).

RL comparisons freeze actual native trajectories, complete reward groups, old/reference-policy scores, masks and objective reductions. CPU references independently recompute the current-policy forward/backward and optimizer step; they do not reproduce stochastic rollout generation. Synthetic reward variation only exercises the training path. It is not a reasoning-quality benchmark. Sampled parameter coordinates are explicitly scoped; a nonzero update on a slice is not full-parameter equivalence. AReaL's actor forward is BF16 while its captured optimizer parameters, gradients, reductions and Adam state are FP32. Do not label that optimizer BF16.

The [ROLL bundle](roll-grpo-evidence.zip) uses official v0.4.0 source with a private launcher enabling the official `torch_npu.contrib.transfer_to_npu` adapter after NpuPlatform selection. Its CUDA-named calls execute real NPU operations; no CUDA backend is simulated. The [community OpenRLHF bundle](openrlhf-community-grpo-evidence.zip) preserves exact compatibility patches for version parsing, official Transformers helper imports and dtype-name serialization through the newer vLLM RPC interface. A zero-update first step caused by default warmup was retained as a failed validation; the canonical case explicitly disables warmup and observes a nonzero original FusedAdam update. Native loss and optimizer mathematics were not replaced. The [three-lane failure history](rlar-failure-history.zip) retains earlier native, dependency and observer failures. Host vLLM metadata is `0.18.0+empty`, and vLLM-Ascend reports placeholder `0.0.0` without Git metadata; runtime file SHA inventories identify the actual snapshot rather than inventing an upstream release commit. Successful host-stack compatibility runs do not establish an exact official Docker matrix match.

The [parameterization supplement](parameterization-supplement.json) explains the 751,632,384 versus 596,049,920 parameter counts. The same checkpoint config requests tied embeddings, but Transformers5.3 declines tying when both embedding and lm_head keys exist; a fresh same-environment CPU probe has separate parameters/storage. Transformers4.57.6 has one aliased Parameter/storage. The difference is exactly one 151,936-by-1,024 embedding matrix. In the same TF5.3 probe, all 155,582,464 embedding/lm_head values are `torch.equal` and have identical full-value hashes; equal initial values do not make their optimizer ownership equal. Original native embedding pointers were not captured. Native optimizer counts, fresh CPU alias observations and sampled native/reference initial-value checks are separate evidence. Do not call these frameworks a common initial training state or rank them across implementations.

MindSpeed-RL's [canonical index](mindspeed-rl/archive-index.json) records real Ascend vLLM rollout of four trajectories with four actions each, followed by one original ChainedOptimizer step over 19 trainable tensors/1,836,544 parameters. Actual captures contain 19 F32 gradients, 19 BF16 before/after parameter tensors and F32 preloss logits/loss. A human observer label saying BF16 main_grad was wrong; the immutable dtype erratum preserves the original data and corrects the label. The signed native objective is `0.0`; its clean CPU reference is `-0.0005752295255661011`. Logged `actor/pg_loss=0.7833` is a mean absolute microbatch statistic and must not replace the signed objective. Fixed old/reference-policy anchors and native advantages are accepted objective inputs; an independent reasoning-step reward/group-normalization audit reproduces the accepted advantages exactly, but separately captured native reward arrays are not claimed. Response lengths define valid actions, including a sampled pad-token ID. Distribution inputs are explicit FP64 log-softmax exports of original F32 logits; captured current-policy action scores are F32. Task-only device/group/registry/control-CPU compatibility changes and the recipe/actual-stack differences remain disclosed.

The Slime NPU recipe, its prescribed Bridge fork and community OpenRLHF adaptations have distinct source identities from untouched upstream NVIDIA implementations. Private compatibility changes and successful subsets are disclosed per attempt. A failed downstream HCCL broadcast is not automatically an HBM/OOM diagnosis: worker logs may show that the peer failed earlier on RPC serialization or initialization.

The [Slime/upstream archive](slime-and-upstream-boundaries.zip), [source-scoped results](slime-upstream-results.json) and [capture verification](slime-capture-verification.json) establish Slime's real native update, not independent numerical equivalence. Its captured slices cover 135,680 coordinates across 16 eligible parameter tensors; parameters were BF16, stored copies are F32, and original gradient storage dtype was not recorded. The sampled update norm is approximately `0.03662982348`. No independent CPU model forward/backward, target-score or distribution comparison was performed for this Slime case.

## Distribution export and numerical interpretation

Portable arrays retain their declared capture/export dtypes; original-to-stored promotions are disclosed per capture. Derived arrays are labeled separately. SFT/MindSpeed-LLM/MindSpeed-RL distributions are exported from raw native/reference logits using an explicit FP64 log-softmax. llama.cpp uses an explicit FP64 log-softmax export cast to FP32 on both sides; LMDeploy retains its explicit offline FP64 log-softmax. Inference collectors retain the actual available preprocessor logit dtype and boundary, rather than assuming all scores are native F32. Derived logprobs must not be described as native probability tensors or post-sampling framework outputs.

Large-vocabulary FP32 log-softmax rows exposed normalization-mass errors beyond a strict `1e-5` structural check. Original rows, masses, rejected reports and subsequent normalization policies are retained. The contract records whether full-vocabulary FP64 renormalization or an explicit FP64 re-export was used. Such normalization checks are artifact invariants, not model-quality acceptance thresholds. A declared per-side cache/parameter representation difference remains visible in `side_conditions`.

The two llama.cpp models had raw-logit maximum absolute errors of approximately 0.0192032 and 0.0171146, with all six Top-1 predictions matching their CPU references. These are observations on the retained fixed histories, not a general precision guarantee. RL gradient/update errors are also retained as measured; a successful training return is not used to hide disagreement.

## Upstream hardware and dependency boundaries

NeMo RL v0.2.0 actually entered its unmodified FSDP1PolicyWorker constructor and failed at NCCL initialization: `Distributed package doesn't have NCCL built in`. Upstream Megatron Bridge v0.6.2 was paired with its exact Megatron Core gitlink; provider startup remained blocked before construction by Transformer Engine. Building the exact official TE source failed because NVCC/CUDA runtime were absent. Vendor NPU adaptations and the Slime-prescribed Bridge fork are separate routes; these results do not establish that all possible Bridge adaptations are impossible.

TensorRT-LLM v0.20.0 official ARM wheel and TensorRT runtime were installed privately. Actual compiled-binding loading and an unchanged native CMake configuration exposed CUDA prerequisites; CMake reported `No CUDA compiler found`. The [official support matrix](https://nvidia.github.io/TensorRT-LLM/reference/support-matrix.html) lists NVIDIA hardware. These failures are reported separately from missing small dependencies and from numerical coverage. No Ascend generation pass is claimed for an untouched NVIDIA backend.

## Replay without accelerator frameworks

From the repository root, install NumPy in the selected Python environment. For the single-archive llama.cpp and RL bundles, the [shared replay utility](../replay.py) verifies every exported SHA256, extracts into a fresh UTC run and invokes the existing tool operations:

```sh
python -B tests/results/gpt-6/replay.py \
  --bundle tests/results/gpt-6/compare-npurecovery-20261020T103823Z/llama-native-evidence.zip \
  --output-root runs
```

Use the same command with `swift-grpo-evidence.zip`, `areal-grpo-evidence.zip`, `roll-grpo-evidence.zip`, `openrlhf-community-grpo-evidence.zip` or `lmdeploy-native-evidence.zip` when the bundle supplies `EXPORT.json` and `REPLAY.json`. Expected values preserve the report's explicit side IDs and ordering. The first parent Swift replay accidentally reversed reference/native order; the failed export was retained privately, the replay manifest was corrected by side identity, and all five comparisons then matched. Native tensors and execution were not rerun or changed.

The SFT and MindSpeed-LLM bundles use indexed volumes so no published file exceeds the GitHub limit. Reassembly uses only the standard library and verifies volume, chunk, logical-file and original binary hashes. The supplied replay adapter calls the retained core tools using NumPy, without loading Torch or pickle. Choose fresh output paths:

```sh
BASE=tests/results/gpt-6/compare-npurecovery-20261020T103823Z
STAMP=$(date -u +%Y%m%dT%H%M%SZ)
python -B "$BASE/sft/reassemble_evidence_v2.py" \
  --index "$BASE/sft/archive-index.json" --volumes "$BASE/sft" \
  --output "runs/compare-sft-unpack-$STAMP"
python -B "$BASE/sft/replay_compact_core_v3.py" \
  --root "runs/compare-sft-unpack-$STAMP" --index "$BASE/sft/archive-index.json" \
  --output "runs/compare-sft-replay-$STAMP"
```

For MindSpeed-LLM, MindIE or MindSpeed-RL, substitute the `mindspeed-llm`, `mindie` or `mindspeed-rl` index/volume directory while reusing the indexed bundle's recorded reassembly/replay adapter. Windows reassembly/replay scripts support extended paths; Linux/WSL or a short extraction root is convenient for deeply nested source-attempt names. Native job reruns require restoring actual task/model paths from the public placeholders and the recorded environment/source manifests. Offline metric replay does not rerun native training. Slime's capture verification is a different operation and supplies no independent model-reference replay.

## Bugs fixed and reusable work

The shipped runtime probe assumed UTF-8 diagnostics but inherited a caller's incompatible stdio encoding. A temporary before/after reproducer showed an ASCII-stdio worker fail on Chinese output before the fix and complete afterward. [runtime_probe.py](../../../../skills/precision-skill/scripts/runtime_probe.py) now defines UTF-8 for the worker pipe and streams, and for its JSON files. The permanent multibyte regression explicitly supplies an ASCII parent stdio policy. The directory-symlink regression skips only Windows error1314 when that OS privilege is unavailable; other errors still fail, and Linux still runs the symlink check.

The shared evidence replay utility now also supports distribution and target-score comparisons. Actual native bundles exercise these additions. Hash checking, side-identity preservation and complete-coordinate replay caught the parent's side-order export mistake before publication.

Reusable candidates demonstrated across tasks include boundary-only rank cleanup, fresh-interpreter reference isolation, copy-only optimizer observations with actual dtype inventories, short persistent IPC paths validated against CANN realpath rules, hash-verified interactive stdio transfer, immutable retry journals and compact safetensor evidence volumes. The volume reassembler/replay helpers are included with this result. Other deployment helpers remain case-specific proposals; they are not claimed as newly shipped precision-skill core tools.
