# Completion and replay guide

## What changed

The previous frozen checkpoint contained14 completed native lanes,28 canonical cases,27 independent references and107 comparisons. This continuation closes its missing Slime reference and adds native/reference cases for NeMo RL, Megatron Bridge and TensorRT-LLM. The selected-source-route matrix is now16 libraries /17 lanes,34 canonical paired cases and138 comparator groups. Of these,136 groups have public numerical payloads; two pretrained Bridge full tensor groups were executed only at private source. Validators are separate operations and are not added to comparator counts. Repeated capture attempts and the tiny zero-reward NeMo official CLI are auxiliary, not extra canonical cases.

[results.json](results.json) owns this matrix. [VALIDATION.json](VALIDATION.json) owns final public hashes, link checks, test and audit receipts. Old published archives and guides retain their historical bytes and claims; read their dates with this supplement. Existing27 reference cases are carried forward, not presented as newly rerun native jobs. The original16-logical-device Ascend instance was reused; no new instance was created. TensorRT-LLM used the available local RTX5060 because its selected NVIDIA backend needs CUDA. The new cases are bounded single-rank checks, not a16-device training/scaling result.

## What remains uncompleted or unestablished

- The historical untouched NeMo NVIDIA/NCCL cohort, official Bridge 0.6.2/TE/CUDA cohort and TensorRT 0.20.0 ARM/Ascend cohort still have their original observed failures. Successful adaptations, fork or different version/hardware do not close those exact historical outcomes. TensorRT has no NPU generation result here.
- No16-device scaling, multirank NeMo FSDP/tied-weight validation, broad model-family coverage, long training, answer-quality or throughput claim is made.
- Slime missing native postclip/full arrays/source gradient dtype, Bridge omitted public pretrained full arrays, TensorRT unmeasured loaded-weight/cache equality and sampled NeMo coverage remain explicit.
- Justified numerical acceptance thresholds were not provided. Every `no_thresholds` result means a valid diagnostic computation, not a numerical pass. Existing measured errors are preserved.

No native jobs remain active. This closes the selected-route workflow/reference checklist and records the remaining scope separately. The continuation is coordinated completion work, not a new blind comparison between agent models.

## Reproduce retained comparisons

Offline comparison needs Python and NumPy, not an accelerator framework. From the repository root, the [shared replay utility](../replay.py) verifies exported hashes and replays all six TensorRT comparisons:

```sh
python -B tests/results/gpt-6/replay.py --bundle tests/results/gpt-6/compare-trtcomplete-20261020T134000Z/tensorrt-llm-native-and-reference.zip --output-root runs
```

For either NeMo archive, extract to a fresh directory, verify `FILES.json`, then invoke its retained `replay_core.py --skill ABSOLUTE_PATH_TO_PRECISION_SKILL --output FRESH_OUTPUT_DIRECTORY`. The worker adapter also accepts `--evidence`; the pretrained adapter reads its own extracted directory. This repeats comparison/validation of retained arrays, not native training. Slime's extracted `replay.py --output FRESH_OUTPUT_DIRECTORY` repeats its four comparisons using bundled tools.

Bridge archives expose root `observations-contract.json`, `distributions-contract.json` and `targets-contract.json`, with `cpu/` and `bridge-npu/` manifests. Use the corresponding standard compare_tensors/compare_distributions/compare_target_scores CLI with explicit side identities. Tiny additionally supplies gradient/update inputs. Pretrained full gradient/update reports and hashes alone cannot be independently replayed without the private arrays. The [previous Guide](../compare-npurecovery-20261020T103823Z/GUIDE.md) retains replay commands for the other107 comparison groups.

## Bugs, reusable work and evidence handling

The TensorRT first-callback coordinate defect is a reproducible upstream bug. A reusable collector should validate stage/history/position coordinates against the authoritative generation API and retain rejected exports. Other demonstrated candidates are fresh-process conversion/training boundaries, full-initial-state mapping plus sampled update contracts, real accelerator-resource routing, short transient IPC paths, isolated CPU inputs, full UTF8 plus binary-header privacy scans, and original/exported SHA inventories. They remain case adapters/candidates in this result, not newly shipped precision-skill core tools. Existing shared replay and comparison tools are reused unchanged.

The parent discovered private Kubernetes/node addresses in two unpushed NeMo Ray logs, quarantined that candidate and issued a text-only corrected supplement. All binary arrays stayed byte-identical. Public package versions that look like IPv4 strings and exact upstream unit-test fixtures are narrowly classified during privacy scanning; real endpoint metadata is redacted. Licenses, source identities, actual precision/casting policies, earlier failures and source-to-export hashes are preserved. No credentials, SSH identities, private endpoints, pretrained model weights or environment trees are included in public evidence. Hash consistency is not independent authenticity.

Validation includes130 Linux repository tests, skill metadata, link/anchor checks, original/export hashes, privacy scans and fresh comparator replay. Independent agents audited Slime, Bridge, NeMo and TensorRT with explicit source-only limits. Those audits inspect preserved evidence; they do not independently repeat every accelerator job. Final exact receipts and byte inventories are in [VALIDATION.json](VALIDATION.json).
